## Key points

### An appliance, not an operating system you use

Most software asks something of you: install it, configure it, keep it patched, notice when it breaks. This asks nothing.

### Four things it does without you

A fleet made of donated machines in other people's homes only works if no one has to maintain it. So the appliance takes on the jobs an administrator would otherwise do.

### One screen, for the rare day you look

If the machine has a monitor, this is what it shows — on the device itself, with no sign-in. It answers the only questions worth asking: is it working, is it protected, and does it need anything.

### Hardware you already have

There is no minimum worth deploying. A small machine reads steadily; a capable one takes on the heavier work as well.

### We install it for you

Indexer OS isn't a download. It's deployed as part of a partnership — we prepare the appliance for the hardware it's going on, install it, and look after it from there.

### The rest of the picture

Run a node on Windows Keep the machine exactly as it is. One line to install, one to remove.

### An old machine can still be useful. Pick the way in that suits it

The appliance suits hardware you can dedicate — it sets itself up on first boot, recovers itself and updates itself, and shows one screen nobody has to watch. If the machine has a job already, the Windows and Docker routes sit alongside whatever else it is doing instead of taking it over.

## Frequently asked

### Does this wipe the machine?

Yes — a machine running Indexer OS is a dedicated appliance, so its disk is used for that and nothing else. That is agreed up front as part of the deployment. For a machine that has to keep its existing system, the Windows route installs alongside it and removes cleanly.

### Do we need someone technical on site?

No. There is nothing to configure and no commands to run. The appliance sets itself up on first boot, and the on-screen console is written for whoever happens to be standing in front of it.

### What if it goes wrong when nobody is there?

That's the normal case, and it's designed for it. Nodes recover on their own after power cuts, dropped connections and restarts, and they update themselves without anyone visiting the machine.

### Does it need a screen?

No. A machine with no monitor simply gets on with the work. The console is there for when you want to look, not because the node needs it.

### Can we stop and take the hardware back?

At any time. Reinstall whatever you like on it — the fleet notices the machine has gone, hands its work to another node, and carries on.
